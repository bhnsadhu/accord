# Architecture

## Layout

```
src/
  app/                 routes (App Router); api/ for JSON endpoints, actions/ for server actions
  components/          UI: strip module, nav, palette, scanner, profile builder, …
  db/                  Drizzle schema (schema.ts, auth-schema.ts generated by Better Auth) and pool
  lib/
    catalog/           parsing, seed, queries, cached wrappers
    reco/              recommender (pure TS; no DB except load.ts/service.ts/present.ts)
    scan/              ScentLens client, image checks, quotas/leases/cache, scan orchestration
    collection/repo.ts per-user data access
    profile.ts         zod schemas for profile, collection entry, guest state
    store.tsx          client state: guest localStorage or account, merge on sign-in
drizzle/               SQL migrations
scripts/               db server, migrate, seed, recommender evaluation
tests/                 integration (real pg driver over in-memory PGlite) and e2e (Playwright)
```

## Database

Postgres via Drizzle and node-postgres. Neon in production (pooled URL, `attachDatabasePool` for Vercel Fluid compute); locally PGlite behind a wire-protocol socket so the same driver is used everywhere.

| Table | Purpose | Key points |
|---|---|---|
| `fragrances` | Catalog | PK is the ScentLens `product_id` (`p05819`), never reassigned. Parsed `wheel`, `character`, `facets[]`; raw `accords_raw`, `notes_raw` kept for provenance; folded `search_text` with a `gin_trgm_ops` index; GIN on `facets`. |
| `brands`, `notes`, `fragrance_notes` | Normalised catalog | Notes keyed by slug; join table keeps source order (`position`). |
| `user`, `session`, `account`, `verification`, `rate_limit` | Better Auth | Generated schema. Rate limits stored in Postgres because serverless instances share no memory. |
| `taste_profiles` | Explicit preferences | One JSONB row per user, validated by zod on read and write. Cascades on user delete. |
| `collection_items` | Shelves, ratings, favourites | PK `(user_id, product_id)`; rating CHECK 1 to 5; cascades on user delete. |
| `scan_quota`, `scan_slots`, `scan_cache` | Scanner protection | See below. No photos stored. |

Authorization: every write path takes the user id from the verified session (`currentUser()`), never from input, and every query on user data is scoped by it. Integration tests cover cross-user isolation and cascade deletion.

## Catalog pipeline

`scripts/seed-catalog.ts` reads ScentLens `products.csv` and upserts by `product_id`, so re-seeding never disturbs collections. The accord phrase (`"Woody Amber Fresher Citrus"`) is parsed into an Edwards-wheel family, a character modifier and facets (`src/lib/catalog/parse.ts`); legacy "Oriental" maps to "Amber"; stray tokens (perfumer names) are dropped. Notes drop parenthetical origins so variants compare equal.

Catalog reads go through `"use cache"` wrappers (`src/lib/catalog/cached.ts`) with `cacheTag("catalog")`, so pages prerender into the static shell and per-fragrance pages are generated on first visit.

## Recommendation engine (`src/lib/reco`)

1. **Index** (`catalog-index.ts`): each fragrance → sparse note vector with smoothed IDF weights, L2-normalised; accord id set (wheel family + facets, namespaced); family, subfamily, character. Built once per server instance (~24.6k items).
2. **Similarity** (`similarity.ts`): 0.55 × note cosine + 0.25 × accord Jaccard + 0.15 × family agreement + 0.05 × same character. Adapted from Fragrance DNA's accord-aware similarity.
3. **Profile** (`recommend.ts`): collection entries become weights (rating 5 → 1 … rating 1 → −1; owned 0.6, wishlist 0.4, tried 0.15, favourite 1). A Rocchio-style centroid (dislikes at 0.6 strength) plus explicit liked notes/accords/families. Explicitly avoided notes exclude fragrances outright.
4. **Scoring**: 0.40 note fit + 0.40 similarity to the nearest liked fragrance + 0.10 personalized PageRank (`graph.ts`) + 0.05 accords + 0.05 family. Weights chosen on the offline evaluation.
5. **Diversity**: MMR (λ = 0.75) over the top 150 with at most two per brand.
6. **Explanations**: built only from the score's own terms: explicitly liked notes present, the top contributing notes together with the liked fragrances that contain them, the closest rated fragrance above a similarity threshold, a preferred accord or family.
7. **Match**: percentile of eligible catalog outscored. Not a probability.
8. **Cold start**: per wheel family, the fragrance nearest the family's note centroid ("archetypes"); no popularity data is implied.

## ScentLens integration (`src/lib/scan`)

Request path for `POST /api/scan` (body: JPEG bytes, resized on the client to ≤ 1024 px):

1. Kill switch: `scannerMode()` is `off` unless `SCANNER_MODE=live` with `SCENTLENS_URL`; `mock` only outside production.
2. Validate: size 1 KB to 2 MB, format by magic bytes (JPEG/PNG/WebP).
3. Cache: SHA-256 of bytes; a result from the last 24 h is returned with no upstream call and no quota.
4. Lease one of two slots (`FOR UPDATE SKIP LOCKED`, 150 s expiry), else `429 busy`.
5. Consume quota atomically for every scope in one transaction (global; user or salted daily guest-IP hash), else `429 quota`.
6. Call `/identify` through `@gradio/client` with a 100 s timeout; validate with zod (`identifyResultSchema`). An abstained result is forced to `product_id: null`.
7. Store the result by hash, release the slot, return the result joined to catalog rows by `product_id`.

The UI never presents an abstention as an answer: abstained candidates render as unstained ghost strips under "Not sure", and confident answers state the calibrated confidence as an estimate (or the label text for the clear-label rule).

## Client state

`AccordProvider` holds profile, collection and the recently-opened trail. Guests persist to localStorage (`accord:guest:v1`); signed-in users persist through server actions with optimistic updates and rollback. On first sign-in the guest state is merged (account data wins on conflicts; liked notes are unioned) and local storage is cleared.
